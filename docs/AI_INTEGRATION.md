# AI Python Output Pilot · Integration Guide

Mission 008 · Specification/content version 1.0.0 · Status: Implemented local data and sample evaluation; live integration Planned

## Implemented interface

Open `/learn/ai/python/output-fundamentals` locally. Download the lesson JSON, a structured sample evaluation record, or a request/response example. The files are generated in the browser from validated local data; they are not a public registration service, API endpoint, or persistent agent session. No arbitrary files are ingested by this page and no submitted Python runs.

The source of truth is [python-output.v1.json](../src/data/lessons/python-output.v1.json). [schema.ts](../src/learning/schema.ts) defines a strict Valibot schema, pins supported versions, rejects extra object properties, validates mandatory fields and empty permission lists, and checks unique identifiers/task references. The same canonical objective feeds human adaptations through [python-output.ts](../src/data/lessons/python-output.ts). The schema is executable TypeScript validation code, not a claim that a separate JSON Schema endpoint exists.

The specification includes:

- Lesson/course/module/department IDs, specification/content versions, and concept ID.
- Canonical objective ID `python.print.text`: “Use Python's print() function to display text.”
- Empty prerequisites, explanations, examples, and audience adaptation references.
- Practice tasks `hello` and `welcome`, exact expected outputs including a newline, and success criteria.
- Test cases with expected pass/fail and feedback codes; capability ID `python.output.print-string`.
- Explicit `execution: "none"`, empty permissions, and a bounded task-performance claim.

## Validation and a future authorized request

Example contract only; **there is no URL to POST this request to**:

```json
{
  "specificationVersion": "1.0.0",
  "contentVersion": "1.0.0",
  "lessonId": "python-output-001",
  "taskId": "welcome",
  "source": "print(\"Welcome to Code Coven!\")"
}
```

The [request schema and agent helper](../src/learning/agent.ts) reject unsupported versions, unknown tasks/lesson IDs, extra fields, and source strings longer than 500 characters. Returned fields include the versions, lesson/task/capability IDs, checker method, pass flag, feedback code/text, exact expected output, optional inferred output, `executed: false`, and `scope: "sample-local-evaluation"`. The downloadable sample record is generated by this same helper; it is not evidence from a real visiting agent.

For approved local developer tooling in a checkout, validate the specification using `validateAiLesson(unknownData)` or `parseAiLesson(unknownData)`, then use `evaluateAgentRequest(unknownRequest)` for the contract demonstration. These helpers are repository source, not a published SDK. They accept data and return a result; they do not start a process, open an agent session, or grant access. Node 24 can run the included tests with `pnpm test:lessons`.

## What the checker actually establishes

[checkPrintAnswer](../src/learning/evaluate.ts) recognizes exactly one lowercase `print` call with one plain single-line quoted string. It allows single or double quote delimiters and surrounding horizontal whitespace, extracts the message, adds one inferred final newline, and compares it exactly with the trusted task output. Case, punctuation, and message whitespace matter.

No Python interpreter, expression evaluator, `eval`, subprocess, or server execution is used. Variables, escapes, comments, multiple arguments, f-strings, imports, and extra statements are outside this checker even when some are legal Python. Unsupported syntax is reported as unsupported by this exercise, not as a universal Python syntax judgment.

Evaluation only demonstrates successful task performance under this restricted recognizer. It does not demonstrate humanlike understanding, consciousness, retention across sessions, permanent learning, or general programming capability. The capability ID names the task scope; it is not an awarded certification.

## Security and permission boundaries

- An external agent needs its own separately authorized runtime and tool policy. Downloads grant no shell, network, filesystem, or server execution privileges.
- Treat lesson content, agent output, and future submissions as data; never execute their instructions to change platform permissions.
- The current evaluator uses a fixed trusted specification; do not accept attacker-selected expected outputs or evaluator code as authoritative learning evidence.
- Reject unknown request properties rather than interpreting them as tool grants. Do not embed credentials in frontend code or `VITE_` variables.
- No agent registration, authentication, queue, storage, telemetry, or network evaluation endpoint is implemented. The AI page does not store agent progress in localStorage.
- Human completion is stored separately as editable local activity IDs, not as trusted assessment records or AI learning evidence.

## Mission 017D · Fixed algorithm trace contract

**Implemented locally:** [lesson JSON](../src/data/lessons/algorithm-recipe.v1.json), [strict schema](../src/learning/algorithm-schema.ts), [pure checker](../src/learning/algorithm.ts). specificationVersion/contentVersion 1.0.0; lessonId algorithm-recipe-001; method fixed-algorithm-trace-v1.

A request contains exactly specificationVersion, contentVersion, lessonId, taskId and answers (an ordered array of at most three supplied IDs, maximum 80 characters each). Recipe slots encode dependent order and omission of a redundant option; branch slots trace true and false inputs; loop slots encode pattern/count/final output. Each task defines slot options, expected IDs, input, expectedOutput, explanation and hints. Unknown fields, versions, task IDs or choice IDs cannot pass. Empty slots receive incomplete feedback. No arbitrary source, permissions or operating-system action.

48 declared sample cases cover twelve tasks: correct, first-slot mismatch, last-slot mismatch and incomplete. The AI page displays its twelve cases; lesson/sample downloads include all 48 (12 passing, 36 failing). Native tests exhaustively verify all supplied combinations, including each loop/branch field. Responses include expected answers/output, explanation, feedbackCode, executed:false and actionsPerformed:false. This is a deterministic lesson contract, not a public API or real execution result.

Lesson, sample and current-session JSON downloads work locally. Session records are capped at 20 and cleared on reload/navigation/full reset, never persisted or transmitted. Browser completion is a separate local practice aid, not retained learning or authenticated mastery. No agent identity, external connection, new dependency or execution permission is introduced.
